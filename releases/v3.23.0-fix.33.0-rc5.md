# v3.23.0-fix.33.0-rc5

> [!NOTE]
> Fifth pre-release of the v33 line: rc4 plus the operator-facing completion work. The Docker container gains the `AUTH` selector with local JWT validation, the operator env passthrough and `ALL_OPERATORS`; the provider ports sn's all-operators surface with the typed 401 and sign-in quarantine, adds `provider snclaim` and `choose_network --show`, and fixes the durable-head publication in three places (the claim queue's cancel window among them); and the CFAA blocklist is refreshed for the v33 tag. The provider code here is the v33 release candidate (`e9dd5b70d`). Not a stable release: it is invisible to `urnet-tools update`. Try it on one box first.

## Highlights

- **Docker `AUTH` selector and operator passthrough.** The entrypoint takes `AUTH=userpass|authcode` (over `BUILD` and `AUTHCODE`, with an explicit `BUILD` still winning a conflict), the start scripts decode a stored JWT locally and drop only an expired one, and the v33 operator environment variables (`ALL_OPERATORS`, `AUTO_REGISTER`, `HOTKEY_SEED_FILE`, `ALLOW_CLIENT_REGISTRATION`, `MAX_MEMORY`, `PROVIDER_ARGS`) map onto provide flags. With `ALL_OPERATORS` set, the single `AUTH` login is skipped because each operator signs in on its own. vnStat and the CGI stats page are retired; `ENABLE_VNSTAT` stays accepted and only logs the retirement warning.
- **Sn's all-operators surface.** `--hotkey_seed_file`, `--auto-register`, `--max-memory`, `--port`, `--allow-client-registration` and `auth --operator` land with the identity gate scoped to operator children, so plain `provide` still mints its key. A rejected network sign-in is typed, set aside and retried by the supervisor, and wallet hotkey commands fan out to every authenticated operator.
- **`provider snclaim` and `choose_network --show`.** Submit a claim from the provider binary, or print the network choice without applying it. Saving now warns on unencrypted URLs and a stale JWT, writes `network.json` atomically, and refuses a half-written file instead of handing on an empty base URL.
- **Durable-head publication.** A stop keeps every prepared record and abandons only an unwritten publication; the create-marker lifecycle gaps are closed; a cancelled publication no longer strands a snapshot temporary. The claim queue's cancel window is closed by the same series.
- **Fleet publication.** A republish closes an unresolved pre-tag publication before the tagged write instead of staying unresolved and blocking bind and revoke, and `publish` refuses a validator or subnet-owner hotkey with no override. The sn pin is advanced to the tagged fleet-commitment release.
- **CFAA blocklist refresh** for the v33 tag.
- **Docs**: the rc5 operator, snclaim and fan-out surface is documented, the docker quick start is rewritten around `AUTH`, vnStat is retired in the container docs and metadata, and the Bittensor pages are reordered for a newcomer.

## Fixed

- Durable-head publication after a stop, create-marker lifecycle, and cancel paths (three separate fixes), covering the claim queue's cancel window.
- A non-200 API response returns a typed error, and a 401 is typed only for operator children; plain `provide` and `auth-provide` keep the original text their scripts match on.
- Fleet publish is refused from validator and subnet-owner hotkeys, and a pre-tag publication is closed before a tagged fleet write.
- Docker builds copy the local replace trees before `go mod download`.
- Test coverage: the client JWT store is kept under a provider start-up, the real provider starts on legacy state dirs, and the identity gate, 401 path and seed secrecy are covered.
- Test ordering: the H3 send harness publication is ordered, and the ICMP echo view skips without ICMP sockets.

## Known limits

- Same as rc4; the client send path for ICMP stays off.
- Prereleases are not offered by `urnet-tools update`.
